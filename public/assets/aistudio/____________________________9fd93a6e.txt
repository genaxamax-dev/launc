КОРОТКО (главное)
--------------------------------------------------------------------------------
1. Исполнитель не показывается потому, что лаунчер ВООБЩЕ не подключён к
   медиасессии Яндекса. Яндекс не пускает сторонние приложения в свой
   MediaBrowserService, а уведомления лаунчер не слушает. Поэтому виджет
   работает в режиме «КЛАВИШИ» и не знает ни трека, ни исполнителя.

2. Кнопки ведут не туда потому, что в коде неверные deep links:
       «Моя волна» -> yandexmusic://radio
       «Коллекция» -> yandexmusic://collection
   Оба дают экран «Нет такой страницы». Рабочие адреса:
       «Коллекция» -> yandexmusic://mymusic/
       «Моя волна» -> yandexmusic://radio/station/user:onyourwave
                      (сильный кандидат, нужна финальная проверка на живом ГУ)

3. Правильное решение: добавить в лаунчер NotificationListenerService и брать
   метаданные через MediaSessionManager.getActiveSessions(). MediaBrowser к
   Яндекс.Музыке оставить необязательным/удалить. Deep links заменить.

2. ПОЧЕМУ ЛАУНЧЕР НЕ ПОЛУЧАЕТ ИСПОЛНИТЕЛЯ (корневая причина)
--------------------------------------------------------------------------------
Лаунчер в MediaIntegrationManager.connectYandexMediaBrowser() подключается
через android.media.browse.MediaBrowser к MusicBrowserService.

В декомпилированном MusicBrowserService.onGetRoot() (метод b(int, String))
есть белый список вызывающих. Пропускаются только:
  - свой же процесс (uid приложения);
  - system uid 1000;
  - пакет из внутреннего allow-list Яндекса;
  - приложение, подписанное платформенной подписью;
  - приложение с разрешением android.permission.MEDIA_CONTENT_CONTROL;
  - приложение с разрешением BIND_NOTIFICATION_LISTENER_SERVICE.

Наш лаунчер — обычное стороннее приложение. Для Яндекса он «unknown caller»,
onGetRoot возвращает null, MediaBrowser получает onConnectionFailed.
Лаунчер уходит в MEDIA_KEYS_FALLBACK -> на экране «КЛАВИШИ» и
«Управление по медиа-клавишам • Готово».

Почему нельзя просто выдать разрешение:
  MEDIA_CONTENT_CONTROL          prot=signature|privileged  (pm grant не даёт)
  BIND_NOTIFICATION_LISTENER_SERVICE  prot=signature        (pm grant не даёт)

Почему не спасают broadcast'ы:
  код слушает ru.yandex.music.metachanged / playstatechanged,
  но Яндекс их фактически не рассылает — данных нет.

Почему не работает прямое подключение к Media3SessionService:
  exported=false, стороннее приложение его не запустит и не привяжет.

4. ЧТО МЕНЯТЬ В ЛАУНЧЕРЕ

4.1. AndroidManifest.xml — добавить сервис-слушатель уведомлений
     (внутрь <application>, рядом с activity):

  <service
      android:name=".media.YandexNotificationListener"
      android:exported="true"
      android:label="@string/app_name"
      android:permission="android.permission.BIND_NOTIFICATION_LISTENER_SERVICE">
      <intent-filter>
          <action android:name="android.service.notification.NotificationListenerService" />
      </intent-filter>
  </service>

4.2. Новый файл
     app/src/main/java/com/example/media/YandexNotificationListener.kt:

  package com.example.media

  import android.content.ComponentName
  import android.content.Context
  import android.service.notification.NotificationListenerService
  import kotlinx.coroutines.flow.MutableStateFlow
  import kotlinx.coroutines.flow.StateFlow
  import kotlinx.coroutines.flow.asStateFlow

  class YandexNotificationListener : NotificationListenerService() {

      companion object {
          private val _connected = MutableStateFlow(false)
          val connected: StateFlow<Boolean> = _connected.asStateFlow()

          @Volatile
          var instance: YandexNotificationListener? = null
              private set

          fun component(context: Context): ComponentName =
              ComponentName(context, YandexNotificationListener::class.java)
      }

      override fun onListenerConnected() {
          instance = this
          _connected.value = true
      }

      override fun onListenerDisconnected() {
          instance = null
          _connected.value = false
      }

      override fun onDestroy() {
          instance = null
          _connected.value = false
          super.onDestroy()
      }
  }

4.3. MediaIntegrationManager.kt — заменить подключение MediaBrowser
     на MediaSessionManager (оставить старый метод как резерв).

  import android.content.ComponentName
  import android.media.session.MediaSessionManager

  private var sessionListener: MediaSessionManager.OnActiveSessionsChangedListener? = null

  private fun connectYandexSession() {
      val listener = YandexNotificationListener.component(context)
      if (YandexNotificationListener.instance == null) {
          _state.update {
              it.copy(
                  connectionMode = MediaConnectionMode.MEDIA_KEYS_FALLBACK,
                  diagnosticStatus = "Нет доступа к уведомлениям • включите Notification access"
              )
          }
          return
      }
      val msm = context.getSystemService(Context.MEDIA_SESSION_SERVICE) as MediaSessionManager
      val cb = MediaSessionManager.OnActiveSessionsChangedListener { sessions ->
          bindYandexSession(sessions)
      }
      sessionListener = cb
      msm.addOnActiveSessionsChangedListener(cb, listener)
      bindYandexSession(msm.getActiveSessions(listener))
  }

  private fun bindYandexSession(sessions: List<MediaController>?) {
      val controller = sessions?.firstOrNull { it.packageName == YANDEX_MUSIC_PKG } ?: return
      if (controller.sessionToken == mediaController?.sessionToken) return
      detachMediaController()
      mediaController = controller
      controller.registerCallback(controllerCallback)
      updateFromMetadata(controller.metadata)
      updateFromPlaybackState(controller.playbackState)
      _state.update {
          it.copy(
              connectionMode = MediaConnectionMode.MEDIA_BROWSER_CONNECTED,
              activeSourceLabel = "ЯНДЕКС.МУЗЫКА",
              diagnosticStatus = "MediaSession подключена (ru.yandex.music)"
          )
      }
  }

  В start() вызвать connectYandexSession() вместо connectYandexMediaBrowser().
  В stop()/disconnectMediaBrowser() снять слушатель:

      sessionListener?.let {
          runCatching {
              (context.getSystemService(Context.MEDIA_SESSION_SERVICE) as MediaSessionManager)
                  .removeOnActiveSessionsChangedListener(it)
          }
      }
      sessionListener = null

  Примечание: detachMediaController() сейчас сбрасывает mode в FALLBACK.
  Чтобы не было мигания при смене трека, сделать у него параметр
  resetMode: Boolean = true и при переподключении вызывать
  detachMediaController(resetMode = false).

4.4. Метаданные (updateFromMetadata) — уже почти всё есть:
  TITLE -> METADATA_KEY_TITLE / DISPLAY_TITLE
  ARTIST -> METADATA_KEY_ARTIST / ALBUM_ARTIST / DISPLAY_SUBTITLE
  У Яндекса subtitle = «Beliy, Xamm», так что после подключения сессии
  исполнитель появится сам. Дополнительно можно разбирать
  METADATA_KEY_DISPLAY_DESCRIPTION, если ARTIST пустой:
      description.split(", ").drop(1).joinToString(", ")

  В YandexNotificationListener:

  override fun onNotificationPosted(sbn: StatusBarNotification) {
      if (sbn.packageName != "ru.yandex.music") return
      val e = sbn.notification.extras

5. КАК ВЫДАТЬ ДОСТУП К УВЕДОМЛЕНИЯМ (один раз, после установки)
--------------------------------------------------------------------------------
Основной способ (Android 9, cmd notification):

  adb root
  adb shell cmd notification allow_listener \
      com.aistudio.havalm6launcher.kqtxzn/com.example.media.YandexNotificationListener
  adb shell settings get secure enabled_notification_listeners

Ожидаемый вывод: строка с нашим компонентом.

Если в прошивке нет команды allow_listener — записать напрямую:

  adb shell settings put secure enabled_notification_listeners \
      com.aistudio.havalm6launcher.kqtxzn/com.example.media.YandexNotificationListener

После переустановки лаунчера доступ обычно сбрасывается — выдать заново.
Добавить этот шаг в install-launcher.sh (после adb install).

9. АЛЬТЕРНАТИВА, ЕСЛИ СЛУШАТЕЛЬ УВЕДОМЛЕНИЙ НЕ ПОДХОДИТ
--------------------------------------------------------------------------------
Сделать лаунчер привилегированным системным приложением и выдать
MEDIA_CONTENT_CONTROL через privapp-permissions whitelist:
  - положить APK в /system/priv-app/...;
  - добавить строку с разрешением в
    /system/etc/permissions/privapp-permissions-*.xml;
  - remount /system (на userdebug возможно), перезагрузка.
Это грубее и рискованнее, чем NotificationListenerService, и требует
перепрошивки раздела system. Рекомендуется только если слушатель
уведомлений почему-то не заработает.
