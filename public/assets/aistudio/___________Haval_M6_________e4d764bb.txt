0. КОРОТКО (самое важное)
----------------------------------------------------------------
 * Android 9 (API 28), automotive-сборка, userdebug, adb root доступен.
 * Экран 1920x720, density 160 dpi ==> 1 dp = 1 px (очень удобно).
 * Система сообщает область приложения 1920x608: слева 120 px
   занимает системная панель навигации (Back/Home/Recents),
   сверху 80 px - статус-бар.
 * Свой лаунчер = обычное приложение с intent-filter HOME+DEFAULT.
 * Штатный com.adayo.launcher перехватывает Home => его надо
   отключать (pm disable-user), иначе ваш лаунчер не станет домашним.
 * Обычный adb install блокируется фильтром прошивки.
   Обход: adb shell service call package 195 i32 1  (перед каждой
   установкой), затем adb install -r -g.
 * logcat на устройстве пустой (logd не отдаёт записи) - отладка
   через dumpsys / uiautomator dump / screencap.
 * Штатные приложения запускаются явными компонентами (см. раздел 5),
   интеграция с источниками звука - через source-менеджер Adayo
   (раздел 6), но его классы лежат в системном vdex, не в SDK.

2. ЭКРАН, ПЛОТНОСТЬ, СИСТЕМНЫЕ ПАНЕЛИ
----------------------------------------------------------------
 Физический экран ..... 1920 x 720 px
 Плотность ............ 160 dpi (density 1.0)
                        ==> 1 dp = 1 px, 1 sp = 1 px
 Частота .............. 60 Гц, один режим (1920x720@60)
 Ориентация ........... landscape, rotation 0
 Display .............. mDisplayId=0, FLAG_SECURE

 Окна SystemUI (рисуются поверх вашего):
   StatusBar      : [0,0] - [1920,80]   (полоса 80 px сверху)
   NavigationBar  : [0,0] - [120,720]   (левая вертикальная панель
                                         120 px: Back/Home/Recents)
   HVAC-оверлеи   : плавающие окна температур водителя/пассажира

 Что сообщает WindowManager:
   init=1920x720 160dpi  cur=1920x720  app=1920x608
   То есть "полезная" область приложения по высоте 608 px,
   низ 112 px система считает занятым (там же удобно делать док).

 Окно самого лаунчера при этом может быть 1920x720 - Fossify,
 например, рисует под панелями и сам отступает на 120 px слева.

 Рекомендации:
 - рабочая зона: x = 120..1920, y = 80..720 (1800 x 640);
 - если делаете док - нижние 112 px (y = 608..720);
 - плотность 1.0 => размеры иконок задавайте в px (или dp, это одно
   и то же), шрифты в sp тоже 1:1;
 - полноэкранный режим: Activity + WindowInsets, не перекрывайте
   левую панель навигации - иначе пользователь не нажмёт Home/Back.


3. КАК СТАТЬ ДОМАШНИМ ЭКРАНОМ
----------------------------------------------------------------
 3.1. Манифест (минимум):

   <activity
       android:name=".MainActivity"
       android:exported="true"
       android:launchMode="singleTask"
       android:stateNotNeeded="true"
       android:excludeFromRecents="true"
       android:screenOrientation="landscape"
       android:configChanges="orientation|screenSize|keyboardHidden|uiMode">
       <intent-filter>
           <action android:name="android.intent.action.MAIN" />
           <category android:name="android.intent.category.HOME" />
           <category android:name="android.intent.category.DEFAULT" />
       </intent-filter>
   </activity>

   Категорию LAUNCHER добавлять не обязательно (у Fossify её нет),
   она лишь показывает лаунчер в списке приложений.

 3.2. Установить и назначить домашним:

   adb install -r -g app-release.apk        (см. раздел 4 - с обходом)
   adb shell cmd package set-home-activity \
       ru.example.carlauncher/.MainActivity

 3.3. Отключить штатный лаунчер (иначе он забирает Home):

   adb shell pm disable-user --user 0 com.adayo.launcher

   Проверить, кто сейчас домашний:
   adb shell cmd package resolve-activity \
       -c android.intent.category.HOME -a android.intent.action.MAIN | head -6
   adb shell dumpsys activity processes | grep mHomeProcess

 3.4. Вернуть штатный экран (откат):

   adb shell pm enable com.adayo.launcher
   adb shell cmd package set-home-activity \
       com.adayo.launcher/.ui.Launcher_MainActivity

 3.5. Если ваш лаунчер упал при загрузке, система покажет
      com.android.settings/.FallbackHome (у него priority -1000).
      Выбраться можно по adb: am start -n ... или вернуть adayo.

 3.6. Замечание из практики: после перезагрузки ГУ один раз
      открылся сервисный экран com.adayo.factory/FactoryMainActivity.
      Лечится запуском лаунчера (am start). Возможно, реакция на
      reboot из adb, но проверьте поведение своего лаунчера после
      холодного старта.


4. УСТАНОВКА СВОЕГО APK (обход фильтра прошивки)
----------------------------------------------------------------
 Прошивка пропатчена: PackageManagerService разрешает установку
 только:
   - штатному магазину (mIsAdayoStore),
   - пакетам из /system/etc/adayo/pm/FilterAppConfig.txt,
   - двум зашитым SHA1 сертификатов.
 Обычный adb install вернёт:
   INSTALL_FAILED_INVALID_APK: INSTALL_FAILED_APK_NOT_ALLOWED_TO_INSTALL

 Штатный магазин перед установкой вызывает
 IPackageManager.setIsAdayoApp(true) - это transaction 195.
 Флаг одноразовый (сбрасывается после установки). Рабочая команда:

   adb shell service call package 195 i32 1
   adb install -r -g app-release.apk

 Готовый скрипт на ПК: ~/havalm6/install-apk.sh app-release.apk
 (он же делает service call перед каждой установкой).

 Примечания:
 - -g сразу выдаёт runtime-разрешения (важно для API 28).
 - если APK собран как test-only, нужен флаг -t.
 - обновление своего приложения тем же способом (service call + install -r).
 - /data доступен на запись, поэтому data-файлы (настройки, БД) вы
   можете менять и через adb root, как это делалось для Fossify.

6. ИНТЕГРАЦИЯ С МАШИНОЙ (источники, клавиши, CAN)
----------------------------------------------------------------
 6.1. Source-менеджер Adayo (переключение аудиоисточников)
   Пакет-сервис: com.adayo.service.sourcemngservice
   Классы (в системном vdex, не в SDK):
     com.adayo.proxy.sourcemanager.SourceSwitchManager
     com.adayo.proxy.sourcemngproxy.ISrcMngProxyClient
     com.adayo.proxy.sourcemngproxy.ISourceActionCallBack
     com.adayo.proxy.sourcemngproxy.Beans.SourceInfo
   Из вашего APK напрямую не слинкуетесь (нет стабов) - либо
   reflection, либо копирование AIDL-стабов из APK штатного лаунчера
   (smali -> java), либо через broadcast-и (ниже).

   Broadcast-и, которые шлёт подсистема
   (список получен разбором APK, на практике не проверялся):
     com.adayo.action.uisourcechange     (смена UI-источника)
     com.adayo.action.sourcerealchange   (реальная смена источника)
     com.adayo.action.frontsourcechange
     com.adayo.action.sourceUIfinish
     com.adayo.action.mediainsert / usbinsert / sdinsert / usbsdchange
     com.adayo.action.screenOffOn
     com.adayo.action.beep
     com.adayo.action.timeZoneChanging
     com.adayo.systemReady
   Интенты для медиа:
     com.adayo.intent.action.music / video / photo / usb / ipod / btaudio / terms

   Имена источников (строки в системе), часто нужные:
     ADAYO_SOURCE_HOME, ADAYO_SOURCE_MEDIA, ADAYO_SOURCE_MULTIMEDIA,
     ADAYO_SOURCE_RADIO, ADAYO_SOURCE_RADIO_FM, ADAYO_SOURCE_RADIO_AM,
     ADAYO_SOURCE_BT_AUDIO, ADAYO_SOURCE_BT_PHONE, ADAYO_SOURCE_NAVI,
     ADAYO_SOURCE_SETTING, ADAYO_SOURCE_AC, ADAYO_SOURCE_AVM,
     ADAYO_SOURCE_DVR, ADAYO_SOURCE_CAMERA, ADAYO_SOURCE_USB,
     ADAYO_SOURCE_USB_VIDEO, ADAYO_SOURCE_USB_PHOTO,
     ADAYO_SOURCE_NET_MUSIC, ADAYO_SOURCE_NET_RADIO,
     ADAYO_SOURCE_CARPLAY_*, ADAYO_SOURCE_ANDROID_AUTO*,
     ADAYO_SOURCE_TPMS, ADAYO_SOURCE_CALLCENTER, ADAYO_SOURCE_ASR,
     ADAYO_SOURCE_VR, ADAYO_SOURCE_SYSTEMUI, ADAYO_SOURCE_NULL.
   Всего в прошивке ~87 таких констант.

   Свойства (меняются при смене источника, но ненадёжны):
     adb shell getprop persist.CURRENT_UID
     adb shell getprop persist.CURRENT_SOURCEID
   Значение - имя источника, например ADAYO_SOURCE_RADIO.
   На практике после запуска сторонних activity значения бывают
   некорректными, поэтому как API не используйте, только для отладки.

 6.2. Аппаратные клавиши
   Служба: com.adayo.service.keyevent (KeyEventService, KeyBroadcaster,
   JNI com.adayo.keyeventjni.IKeyNotifyCB, MCU-прокси
   com.adayo.mcucommproxy).
   Физические кнопки и ручки идут через MCU, часть превращается в
   обычные KeyEvent (Generic.kl), часть - в broadcast-ы.
   KEYCODE_HOME/BACK/MEDIA_* работают стандартно; перехват Home
   системой не отдаётся (Home всегда уходит домашнему экрану).

 6.3. Климат / CAN / данные авто
   com.adayo.hvacservice, com.adayo.service.canbox,
   com.adayo.midware.bcmservice, com.adayo.service.shareinfo.
   В системе есть CarService (boot.car_service_created=1) и
   android.car, но CarPropertyManager требует android.car.permission.*,
   которые выдаются только системным/подписанным приложениям.
   Для обычного APK практичнее: запуск штатных activity + приём
   broadcast-ов + чтение getprop.

   adb shell am force-stop <pkg>

 Пакеты и компоненты:
   adb shell pm list packages -3          (сторонние)
   adb shell pm dump <pkg> | grep -E "versionName|flags=|codePath"
   adb shell cmd package query-activities --brief -a android.intent.action.MAIN \

 Поиск причины падения без logcat:
   adb shell dumpsys dropbox --print | tail -100
   adb shell ls /data/tombstones /data/anr

 adb: устройство требует root для /data; на этом ГУ adb root работает
 (userdebug). После перезагрузки root слетает - adb root заново.


9. ПОДВОДНЫЕ КАМНИ
----------------------------------------------------------------
 * logcat пустой (logd формально работает, но записей нет) - не
   рассчитывайте на него, используйте dropbox/tombstones.
 * Установка APK блокируется фильтром (раздел 4). Забыли service call -
   получите INSTALL_FAILED_APK_NOT_ALLOWED_TO_INSTALL.
 * Штатный лаунчер агрессивно забирает Home. Пока он включён,
   set-home-activity может «не сработать» (проверено на практике).
 * /system и /vendor read-only, dm-verity. adb remount не поможет.
   Ставить свой лаунчер в /system (priv-app) без отключения verity
   нельзя, а это уже вмешательство в прошивку - лучше не надо.
 * Платформенной подписи нет: системные permission и внутренние
   API (в т.ч. android.car в полном объёме) недоступны.
 * Плотность 1.0: не используйте «телефонные» размеры из макетов
   (360dp) - получите микроскопический UI. Считайте в px экрана.
 * Левая панель 120 px системная: если перекрыть - потеряете кнопки
   Back/Home. Учитывайте insets (getWindowVisibleDisplayFrame или
   WindowInsets).
 * Ориентация фиксированная landscape; screenOrientation="portrait"
   на этом дисплее всё равно даст 0-градусный поворот, но лучше
   явно landscape.
 * После перезагрузки бывает показ com.adayo.factory - проверяйте,
   что ваш лаунчер поднимается первым (он и есть HOME, так что должен).
 * Штатный лаунчер несёт климат/медиа-виджеты; при его отключении
   эти панели пропадают - это ожидаемо.


10. МИНИМАЛЬНЫЙ СКЕЛЕТ ПРОЕКТА
----------------------------------------------------------------
 build.gradle (app):
   android {
       compileSdk 34          // можно любой современный
       defaultConfig {
           applicationId "ru.example.carlauncher"
           minSdk 26
           targetSdk 28       // ведём себя как «родное» приложение Android 9
           versionCode 1
           versionName "1.0"
       }
       compileOptions { sourceCompatibility JavaVersion.VERSION_1_8
                        targetCompatibility JavaVersion.VERSION_1_8 }
   }
   Никаких ndk/ABI-фильтров не нужно - чистый Java/Kotlin.

 Манифест - см. раздел 3.1. Тема - без ActionBar:
   <style name="AppTheme" parent="android:Theme.Material.NoActionBar">
       <item name="android:windowBackground">@android:color/black</item>
       <item name="android:windowFullscreen">false</item>
   </style>

 Перечисление установленных приложений и запуск:

   PackageManager pm = getPackageManager();
   Intent q = new Intent(Intent.ACTION_MAIN)
           .addCategory(Intent.CATEGORY_LAUNCHER);
   List<ResolveInfo> apps = pm.queryIntentActivities(q, 0);
   for (ResolveInfo ri : apps) {
       String pkg = ri.activityInfo.packageName;
       String cls = ri.activityInfo.name;
       CharSequence label = ri.loadLabel(pm);
       Drawable icon = ri.loadIcon(pm);
       if (pkg.equals(getPackageName())) continue;  // себя не показываем
       // добавляем в свою сетку
   }

   // запуск по тапу
   Intent i = new Intent(Intent.ACTION_MAIN)
           .addCategory(Intent.CATEGORY_LAUNCHER)
           .setComponent(new ComponentName(pkg, cls))
           .addFlags(Intent.FLAG_ACTIVITY_NEW_TASK);
   startActivity(i);

 Запуск штатной функции (пример радио):
   startActivity(new Intent().setComponent(new ComponentName(
           "com.adayo.ora.radio",
           "com.adayo.ui.main.Radio_MainActivity")));

 Сохранение раскладки: SharedPreferences или Room; учтите, что при
 обновлении приложения данные сохраняются, а при uninstall - нет.

 иконки 96-128 px, подпись 24-28 px (при density 1.0 это sp=px).
 Для дока - нижние 112 px (y=608..720).
